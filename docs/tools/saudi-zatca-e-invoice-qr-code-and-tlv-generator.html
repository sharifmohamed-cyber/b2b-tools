Complete Technical Guide to ZATCA E-Invoicing QR Code Requirements in Saudi Arabia

Under the Kingdom of Saudi Arabia's Electronic Invoicing (Fatoora) Regulations issued by the Zakat, Tax and Customs Authority (ZATCA), all taxable persons resident in the Kingdom are required to issue electronic invoices containing a standardized, machine-readable Two-Dimensional Barcode (QR Code). For Simplified Tax Invoices (B2C) and Standard Tax Invoices (B2B summary representations), the QR code must adhere strictly to the Tag-Length-Value (TLV) encoding format converted into a UTF-8 Base64 string. Plain text QR codes containing plain URLs or JSON are non-compliant and subject to regulatory penalties.

Phase 1 (Generation Phase - مرحلة الإصدار)

Enforced since December 4, 2021. Any cash register or billing system issuing Simplified Tax Invoices must encode 5 mandatory fields into the TLV Base64 QR code:

  • Tag 1: Seller’s commercial or branch name (UTF-8).
  • Tag 2: 15-digit VAT registration number (starts & ends with 3).
  • Tag 3: Invoice issuance date & time in ISO 8601 format (YYYY-MM-DDTHH:mm:ssZ).
  • Tag 4: Total invoice amount with VAT included (as string formatted decimal).
  • Tag 5: Total VAT liability amount.

Phase 2 (Integration Phase - مرحلة الربط والتكامل)

Rolling out in phased compliance waves since January 1, 2023. Adds advanced cryptographic security to prevent invoice tampering and backdating:

  • Tag 6: Invoice Hash (SHA-256 digested invoice XML).
  • Tag 7: ECDSA Digital Cryptographic Signature (secp256k1).
  • Tag 8: Public Key of the Cryptographic Stamp identifier (X.509 cert).
  • Tag 9: Cryptographic Stamp Identifier (for certified devices).

How the TLV (Tag-Length-Value) Byte Structure Works

TLV is a compact binary serialization protocol where each data element consists of three sequential byte components:

Component Byte Size Description & Example
Tag (Identifier) 1 Byte Sequential integer from 1 to 9 (e.g. 0x01 for Seller Name, 0x02 for VAT number).
Length 1 Byte (or variable) The byte count of the UTF-8 encoded value string (e.g., 15 bytes = 0x0F).
Value Variable Bytes The actual UTF-8 byte payload (Arabic letters typically take 2 bytes each in UTF-8).

Once all tags are serialized sequentially into a contiguous byte buffer, the entire byte array is encoded into standard Base64 representation. This Base64 text is then printed directly as an ISO/IEC 18004 QR Code.

Frequently Asked Questions (الأسئلة الشائعة)

1. What happens if I put a simple website URL or JSON in my Saudi invoice QR code?

ZATCA field inspectors utilize the official Fatoora inspection mobile application. Scanning a non-TLV QR code fails verification instantly, triggering statutory fines under the VAT implementation regulations for non-compliant billing systems.

2. Why does my Arabic seller name show corrupted characters in standard QR readers?

Arabic text must be encoded using UTF-8 byte streams rather than ASCII or Windows-1256. When calculating the "Length" byte in TLV, you must count the UTF-8 bytes rather than the character length (each Arabic letter equals 2 bytes). This web tool handles multi-byte UTF-8 string encoding natively.

3. Does a B2B Standard Tax Invoice require a QR code?

Under Phase 1, QR codes were strictly mandatory on Simplified Tax Invoices (B2C) and optional for Standard Tax Invoices (B2B). Under Phase 2, when integrated with the Fatoora Portal, the portal returns the cryptographic stamp which must be printed as a QR code on both B2B and B2C invoices.

4. How do I generate this inside Microsoft Excel without third-party web calls?

Pure VBA functions can assemble the byte array and convert binary data into Base64 using Microsoft XML Core Services (MSXML2). You can then bind the string to a 2D font or an embedded active shape. Check out our ready-to-deploy Excel Master Template available above.
